# 《High》测试计划（v0.1 框架）

> 2026-09-17 建立。随项目推进补充。

## 一、测试范围

| 对象 | 说明 |
| --- | --- |
| 游戏逻辑 | 资源产出 / 建筑 / 科技 / 阶段切换 / 小人状态机 |
| 数值系统 | 产出速率、升级成本、增长曲线、离线收益 |
| 存档 | localStorage 读写、刷新不丢、版本迁移、坏档容错 |
| 场景层 | 网格地图渲染、小人动画、寻路正确性 |
| UI | 面板显示、按钮交互、数字刷新、响应式布局 |
| 部署 | itch.io 链接可访问、手机浏览器可玩 |

## 二、测试环境

- **桌面浏览器**：Chrome 最新版（主）、Edge。
- **手机浏览器**：Chrome（Android）/ Safari（iOS）——里程碑 3 起必须覆盖。
- **工具**：浏览器 DevTools（网络、存储、性能）、Vitest（单元测试）、Playwright（可选，端到端）。

## 三、测试类型与策略

1. **单元测试**（开发组写，测试组监督覆盖）：game/ 下纯逻辑模块，Node 直跑。
2. **功能测试**（手动 + 用例化）：按用例清单逐条执行。
3. **数值验证**：用脚本或表格对比"预期产出 vs 实际产出"，重点验离线结算。
4. **兼容测试**：里程碑 3 起，PC + 手机浏览器各跑一遍冒烟用例。
5. **回归测试**：每次里程碑交付前，全量回归已验收用例。

## 四、缺陷管理

- 记录格式：`BUG-日期-序号 | 模块 | 严重级 | 复现步骤 | 期望 | 实际 | 状态`
- 状态流转：新建 → 已确认 → 修复中 → 已验证 → 关闭。
- 正式对外版本（里程碑 3 起）同步提报到禅道。

## 十三、存档事故与防护（ADR 035，2026-09-19）

- 防护：saveGame 写前备份 .bak；loadGame 失败备份 .corrupt 再重建。单测覆盖。
