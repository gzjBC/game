# 测试组 · 组说明

> 《High》质量保障小组。测试是本项目的强制环节：每个模块、每个里程碑、每次发布都必须过测试。

## 职责

- **功能测试**：资源、建筑、科技、小人行为是否符合设计。
- **数值 / 平衡验证**：产出速度、升级成本、离线收益是否符合预期曲线。
- **离线收益专项验证**：关浏览器再打开，结算是否正确（时间差算法、防作弊）。
- **存档测试**：刷新不丢档、版本迁移、损坏存档的容错。
- **兼容性测试**：Chrome / Edge / 手机浏览器（响应式布局、横向不溢出）。
- **缺陷管理**：发现的问题按规范记录（本地 cases/ 或禅道）。

## 产出物位置

```
测试组/
├── 测试计划.md      测试范围、环境、策略（总纲）
└── cases/           测试用例（按里程碑分文件）
```

## 测试规范

1. **用例模板**：`编号 | 前置条件 | 操作步骤 | 预期结果 | 实际结果 | 状态 | 备注`。
2. **每个里程碑交付前**：跑完该里程碑的全部用例 + 全量回归上一里程碑用例。
3. **缺陷记录**：`BUG-日期-序号`，含复现步骤、期望、实际、截图（如适用）。
4. **验收标准来源**：`docs/02_路线图.md` 每个里程碑的"验收"栏，逐条对照。
