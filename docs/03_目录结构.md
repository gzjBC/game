# 目录结构

> 本文件描述代码组织。原则：高内聚、低耦合、按模块分文件夹、每模块自带测试。
> 目录按职能分三个组：**图像绘画组 / 游戏开发组 / 测试组**。下文 `src/` 均指 `游戏开发组/src/`。

## 模块划分原则

1. **game/ 不 import React / Phaser**。它只 import 自己的子模块和 types。
   - 这样才能在 Node 里单测，不启浏览器。
2. **scene/ 不 import React**。它通过全局事件总线（Phaser 的 events）或 zustand subscribe 拿数据。
3. **ui/ 不 import Phaser**。它只读 zustand，点按钮时调 zustand action。
4. **数值集中在 game/systems/balance.ts**。调平衡只改这一个文件。
5. **静态配置在 game/data/*.json**。加新建筑不改代码，改 JSON。
6. **每模块必须有 __tests__**。用 Vitest（Vite 自带）。
7. **每完成一个模块**：写完代码 → 写测试 → 跑通 → git commit。commit message 用 `feat(模块): 一句话`。

## Git 规范

- 主分支 `main`，日常在 `dev` 或 feature 分支。
- 每个里程碑打 tag：`v0.1-m0`、`v0.2-m1`、...
- commit 前缀：`feat / fix / refactor / docs / test / chore`。
- `.gitignore` 要忽略：`node_modules/`、`dist/`、`build/`、`.vscode/`、`*.log`。

## 命名规范

- 文件：`kebab-case.ts`（比如 `offline-settlement.ts`），组件用 `PascalCase.tsx`。
- 类型：`PascalCase`（`WorkerState`）。
- 函数 / 变量：`camelCase`。
- 常量：`UPPER_SNAKE`。
