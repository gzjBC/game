# 《High》QA 视角：500h 时长与纵深设计（04e）

> 2026-09-17 · 配合 04d 使用。本文只回应"总时长拉到 500h"这个新目标带来的 QA 问题，不推翻 04d 已确认的 GWT 用例和里程碑策略。
> 算术基线：500h = 1,800,000 秒；×1000 debug 倍速 = 1800 秒 ≈ 30 分钟跑完一轮主线；localStorage 上限 5MB = 5,242,880 字节。

---

## 1. 500h 内容怎么测

### 1.1 核心矛盾

500h 不可能人测。QA 策略必须是：**99% 靠倍速脚本自动跑，1% 抽样人测手感**。这一节先把"哪些是脚本测、哪些是人测"切清楚。

| 内容类型 | 测法 | 频率 |
| --- | --- | --- |
| 数值曲线（每小时产出/成本） | 倍速脚本自动断言 | 每次发版 |
| 主线通关链路 | 倍速脚本 30 分钟跑一轮 | 每次发版 |
| 多周目循环 | 脚本跑 3~5 轮，人不测 | 里程碑级 |
| 成就/图鉴触发 | 脚本遍历每个 ID | 每次发版 |
| 手感、引导、弹窗观感 | 人测，只测第 1h 和每阶段 checkpoint | 里程碑级 |
| 500h 存档耐久 | 脚本跑 500h 压缩时间 + 中途 10 次刷新 | 每个大版本 |

### 1.2 全通关回归脚本（×1000 倍速，目标 30 分钟跑完）

脚本要做的事（写进 `scripts/smoke_full_run.ts`，CI 里跑）：

- [ ] 注入固定 seed（S0），新开档。
- [ ] 注入假时钟 + ×1000 倍速 + 自动点击器（按顺序点：采浆果→生火→招人→建房……）。
- [ ] 每到一个 checkpoint 暂停脚本，断言下表：

| checkpoint | 压缩后累计耗时 | 必须断言 |
| --- | --- | --- |
| M1 山洞通关 | ~30s | 资源不为负；存档 version=1；无 NaN/Infinity |
| M2 村庄通关 | ~90s | 5 小人在场；制陶科技点上；存档大小 < 50KB |
| M3 小镇通关 | ~3min | 阶段切换动画播完；旧建筑不残留 |
| M4 城市通关 | ~8min | 税收/科研点系统在跑；大数到 e50 仍正常显示 |
| M5 国家通关 | ~15min | 稀有矿产线通；存档大小 < 200KB |
| 太空阶段通关（戴森球） | ~25min | 星尘入账；通关画面触发 |
| 第 2 周目开始 | ~28min | 星尘加成生效；存档不清空 |
| 第 2 周目通关 | ~30min | 星尘叠加正确（加法/乘法按 04c 拍板） |

- [ ] 全程每 60 秒自动 dump 一次：当前资源、存档大小、内存占用（用 `performance.memory`，Chromium only）。
- [ ] 脚本退出条件：要么全过，要么第一个断言失败就停，输出现场快照。

### 1.3 多周目循环怎么测

| # | 场景 | 断言 |
| --- | --- | --- |
| C1 | 脚本连续跑 3 个完整周目 | 每周目通关后星尘正确累加，无漏发无重发 |
| C2 | 跑 5 个周目后刷新存档 | meta 层（星尘/成就/图鉴）全保留；run 层按设计重置 |
| C3 | 跑 10 个周目（≈ 500h 的主要内容量） | 存档大小增长可控（见 §4.1）；大数不破；无"第 N 周目特有的 bug" |
| C4 | 周目之间穿插 10 次离线 8h | 离线收益在每一周目都正确，不和星尘加成串味 |

**抽测原则**：不需要人玩 500h。脚本跑 10 周目 = 覆盖 500h 数值和存档压力；人只在第 1、第 10、第 100 周目（对应 1h/10h/100h 真实时间）抽样玩 10 分钟，看手感。

## 2. 图鉴 / 成就 / 收藏系统测试矩阵

### 2.1 成就触发不丢、不重复

> 沿用 04d §8.5 的 A1~A6，500h 目标下追加：

| # | 场景 | 断言 |
| --- | --- | --- |
| AC1 | 所有成就 ID 清单 | 脚本遍历：每个成就都能被某个动作触发，**没有"永远拿不到"的死成就** |
| AC2 | 成就条件是"累计 X 次"（500h 玩家会反复触发） | 计数只增不减；刷新不重复弹窗 |
| AC3 | 同一帧同时满足 3 个成就 | 排队弹窗，不叠、不丢 |
| AC4 | 周目重置后 | 跨周目成就保留；本周目成就按设计重置（写死规则） |
| AC5 | 500h 后成就列表 | UI 不卡（100+ 成就的列表要虚拟滚动）；搜索可用 |
| AC6 | F12 改存档伪造成就 | v1 容忍，但要记录"可疑成就"（v2 服务端校验用） |

### 2.2 图鉴解锁事件

| # | 场景 | 断言 |
| --- | --- | --- |
| BC1 | 第一次看到某建筑/小人/物品 | 图鉴卡弹出 + 解锁；存档里图鉴位 +1 |
| BC2 | 同一东西第二次看到 | 不重复弹窗，图鉴里已点亮 |
| BC3 | 图鉴有 100 个条目时 | 解锁动画不拖帧；列表滚动流畅 |
| BC4 | 老存档 v1 没有图鉴字段 | 迁移为空对象；进游戏后第一个新东西正常触发 |
| BC5 | 图鉴收集率 | 显示百分比 = 已解锁/总数，数学上对（分母不因为新加条目把老进度算成负） |

**风险点**：图鉴条目会随版本加。v1 加了 50 个，v1.1 加 10 个——老存档的"收集率"分母必须用"当前版本总条目数"，不是"解锁时的总数"。否则老玩家会看到"我已经 100% 了，更新后变 83%"，体验崩。

## 3. 世界种子重开测试

> 沿用 04d §8.2 的 S1~S6，500h 目标下追加：

### 3.1 同种子两次开档必须确定吗？

**QA 立场：v1 不强求"完全确定"，只承诺"软种子范围内确定"**（初始地形、前 N 个事件、名字）。理由：Phaser 渲染时序、GC 停顿、动画帧都会引入抖动，追完全确定成本极高，不值得。

但要把"确定"的边界写死：

| # | 场景 | 断言 |
| --- | --- | --- |
| WD1 | 同 seed ×2 | 初始地形、前 50 个随机事件序列、小人名完全一致 |
| WD2 | 同 seed ×2，跑 10 周目 | 星尘总数、成就解锁顺序在脚本下一致（因为 RNG 注入了） |
| WD3 | 同 seed ×2，真实玩家手玩 | 允许有差异（因为玩家点击顺序不同），但**不允许**出现"同 seed 某局必卡关" |

### 3.2 种子坏了 / 种子冲突

| # | 场景 | 断言 |
| --- | --- | --- |
| BD1 | 存档里 seed = `""` | 回退到随机，不崩 |
| BD2 | seed = 超长字符串（10000 字符） | hash 截断，不爆栈 |
| BD3 | seed = 用户手动从另一个游戏复制来的怪字符串（含 emoji / 中文） | 用稳定 hash 算法，不抛 |
| BD4 | 两个玩家用同一 seed | 结果一样（这是特性不是 bug，但要在 FAQ 里说清"种子只是装饰，不影响平衡"） |
| BD5 | seed 对应的随机表版本号变了（v1.1 改了事件池） | 老 seed 跑出来的事件序列允许变，但要有 warning："此存档来自旧版本种子" |

## 4. 存档在 500h 时长下的健壮性

### 4.1 存档膨胀预警阈值

| 存档大小 | 处理 |
| --- | --- |
| < 200KB | 正常，不管 |
| 200KB ~ 1MB | 健康，记录日志 |
| 1MB ~ 3MB | **黄灯**：开发期警告，UI 里开始显示"存档较大" |
| 3MB ~ 5MB | **红灯**：UI 弹提示"存档接近上限，请清理旧日志/统计"，提供"只保留 meta，清空旧统计"按钮 |
| > 5MB | **红灯+**：localStorage 写不进去了，必须走 §4.3 的 IndexedDB 方案 |

**测试方法**：脚本跑 10 周目后量存档大小，断言 < 200KB（500h 玩家的存档应该在 200KB~1MB 量级）。如果 10 周目就超过 1MB，说明存档里塞了不该塞的东西（日志、Phaser 对象、重复快照），打回。

### 4.2 localStorage 5MB 上限怎么测

| # | 场景 | 断言 |
| --- | --- | --- |
| LS1 | 手动在 localStorage 里塞满其他数据到 4.9MB | 游戏 save() 触发 QuotaExceededError，走 04d C4 的错误分支 |
| LS2 | 500h 玩家存档 | 不触发 LS1；如果触发，UI 提示清楚 |
| LS3 | 存档写一半崩（模拟：写第 1 个 key 成功，第 2 个失败） | 主存档 key 不受损（临时 key 方案，见 04d §2.4） |
| LS4 | 连续 100 次 save() | 最后一次成功，中间不产生僵尸临时 key |

### 4.3 什么时候必须迁 IndexedDB

**QA 建议阈值**：不是按时间，是按大小——存档 > 3MB 时，**自动迁移到 IndexedDB**，localStorage 只留一个指针。

| # | 场景 | 断言 |
| --- | --- | --- |
| ID1 | 新存档 | 默认存 localStorage，不碰 IndexedDB |
| ID2 | 存档涨到 3.1MB | 自动迁移到 IndexedDB；localStorage 留 `{ "v": 1, "backend": "idb" }` 指针 |
| ID3 | 迁移后刷新 | 从 IndexedDB 读档，玩家无感 |
| ID4 | 迁移到 IndexedDB 后又玩了 100h | IndexedDB 大小继续涨，不爆（IndexedDB 配额通常 50MB+） |
| ID5 | 浏览器禁用 IndexedDB（极端） | 回退到 localStorage + 截断日志，不白屏 |

**为什么现在就提**：500h 目标下，localStorage 一定撑不住，不如现在就把读写层抽象成 `SaveBackend` 接口，localStorage 和 IndexedDB 是两个实现。**别等 3MB 了才重构。**

### 4.4 多次 prestige 后存档版本迁移

| # | 场景 | 断言 |
| --- | --- | --- |
| MI1 | v1 存档 → v1.1（加了图鉴字段） | 图鉴为空对象，老存档能进 |
| MI2 | v1.1 → v1.2（改了星尘加成公式） | 老星尘按新公式重算，数学上对 |
| MI3 | v1 → v2（假设真做了硬 Prestige，meta/run 分层） | 老存档自动拆成 meta + run，星尘在 meta，建筑在 run |
| MI4 | 连续跑 5 个版本迁移 | 每一步都有迁移脚本，且能从最早的 v0 一键迁到最新 |
| MI5 | 迁移失败（中间某版本数据损坏） | 不覆盖老存档，备份原 key 到 `save.backup.时间戳`，让用户能回滚 |

**回归要求**：CI 里保存一份 v0 / v1 / v1.1 的 fixture 存档，每次发版自动跑迁移测试，不能靠人手动点。

## 5. 小白玩家 500h 不劝退的体验检查表

> 挂机游戏最大的敌人不是难，是"不知道现在该干嘛"。500h 意味着玩家会在第 1h、10h、100h、500h 四个点重新面对这个问题。

### 5.1 四个时间点应该看到什么新东西

| 真实时长 | 玩家状态 | 该看到什么 | 不该做什么 |
| --- | --- | --- | --- |
| 第 1 小时 | 刚上手 | 同 04d §3：气泡引导、第一个建筑、第一次离线结算 | 别塞科技树、别塞图鉴、别弹成就 |
| 第 10 小时 | M2~M3 | 第一次阶段切换；图鉴解锁 5~10 个；第一个"咦这是什么"的随机事件 | 别突然加新货币；新系统要跟着阶段解锁，别一次全倒 |
| 第 100 小时 | M4~M5 | 第一条流派点完；第一次硬数值墙（需要挂机过夜）；每日挑战刚上线 | 别在数值墙前弹"看广告加速" |
| 第 500 小时 | 终局 | 所有成就 80%+；星尘好几周目；开始研究"我能不能不走寻常路" | 别给"新玩家"的引导，别把新手气泡再飘出来 |

### 5.2 最容易弃游的三个时间点

| 弃游点 | 为什么弃 | 怎么拉回来 |
| --- | --- | --- |
| **第 30~60 分钟**（M1→M2 之间） | 引导结束了，不知道下一步干嘛 | 进度条上明确标"再采 X 浆果就能建房"；5 分钟没操作就飘气泡 |
| **第 8~15 小时**（第一次软 cap） | 资源涨不动了，要挂机过夜 | 离线收益弹窗要漂亮；睡前给个"明天早上就能建 XX"的预告 |
| **第 100~150 小时**（第一次周目结束） | 通关了，不知道"我为什么还要玩" | 星尘加成 + 新流派预告 + 图鉴收集率，给一个明确的"下周目目标" |

### 5.3 体验检查 checklist

- [ ] 第 1 小时：随机挑 3 个没玩过挂机游戏的人，每人玩 1 小时，不说话不提示，观察他们卡在哪。
- [ ] 第 10 小时：让一个人玩到 M3 通关，问他"下一步想干嘛"，答案必须是游戏里已经给的东西。
- [ ] 第 100 小时：脚本跑 100h 压缩时间后，看 UI 上有没有"这玩意儿是干嘛的"按钮没人点过（埋点）。
- [ ] 第 500 小时：找一个玩家玩 1 周目（≈ 真实 500h 的等价物），看他会不会因为"新内容出得太慢"弃游。
- [ ] 数值墙前：玩家第一次卡 8 小时以上时，弹窗有没有给明确目标。
- [ ] 老玩家回归：3 天没上线，回来离线收益弹窗 + "你不在的时候发生了 X、Y、Z"摘要。

## 6. P0 / P1 / P2 风险清单（500h 目标带来的新风险）

### P0（不解决就发不了版）

- [ ] **大数爆炸**：500h 后资源会到 e50 ~ e100。break_infinity.js 在 e308 附近会变 Infinity。脚本跑 10 周目必须不断言 Infinity。
- [ ] **存档撑爆 localStorage**：10 周目后存档 > 3MB，必须有 IndexedDB 迁移路径，否则一半玩家玩到 100h 就存不进档。
- [ ] **倍速脚本必须真的 30 分钟跑完**：如果脚本跑一轮要 2 小时，CI 就废了，回归等于没有。
- [ ] **成就/图鉴必须遍历测试**：500h 意味着玩家会把所有成就都拿到，任何一个"永远触发不了"的成就都是投诉点。

### P1（不解决会被骂，但能发）

- [ ] **弃游曲线**：第 30~60 分钟和第 100~150 小时两个弃游点必须有数据埋点，否则改了不知道改没改对。
- [ ] **多周目数值叠加**：星尘 + 流派 + 科技，500h 后倍率叠乘可能到 1000 倍，公式写错一个符号就崩。
- [ ] **存档版本迁移 fixture**：CI 里必须有 v0 / v1 / v1.1 老档，不能靠人手动测。
- [ ] **老玩家回归体验**：3 天没上线回来，不能因为"新功能"让他一脸懵。

### P2（锦上添花，发了再说）

- [ ] **跨时区每日挑战**：UTC 日期判定，v1 可以先做本地日期，v2 修。
- [ ] **图鉴收集率分母动态**：新加条目时老玩家进度不能倒退，先记下来，v1.1 之前做。
- [ ] **云存档**：localStorage 清缓存就全没了。500h 玩家丢档是灾难，但 v1 单人开发做不起，写进 v2 规划。
- [ ] **成就分享**：玩家想晒"我 500h 了"，v1 不做。
