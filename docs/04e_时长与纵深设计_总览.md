## 1. 口径：为什么是"主线短 + 纵深累计 500h"

四方一致同意这个分层，不再讨论：

| 层 | 时长 | 服务谁 | 内容 |
| --- | --- | --- | --- |
| **首次体验** | 前 20 分钟 | 朋友试玩 / itch.io 路人 | 看小人采浆果、点火、到村庄 |
| **主线通关** | 首次 18h（纯在线）/ 10h（含正常离线） | 想看完剧情的玩家 | 六阶段走完、火箭升空 |
| **内容纵深** | 累计到 500h | 真正留下的核心玩家 | 转生循环、戴森球、图鉴、成就、挑战 |

**为什么不把主线拉长到 100h**：
- 单人业余开发，主线做 100h 内容量等于做 10 个游戏；
- 作品集阶段最重要的是"能通关"，不是"长"；
- 挂机游戏的留存模型本来就是"短主线 + 长 meta"，对标 Cookie Clicker / Kittens Game 都是这个结构。

## 3. 关键数值调整（解决主策划发现的矛盾）

主策划发现 04c 之前的星尘公式 `floor(log10(rare_ore)/2)` 按当前太空产出，单次主线只给 1 星尘，和循环表对不上。数值策划修正如下：

| 项 | 旧值 | 新值 | 理由 |
| --- | --- | --- | --- |
| 星尘公式 | `floor(log10(rare_ore)/2)` | `floor(log10(rare_ore))` | 每次通关给 N+7 点，第 16 轮单轮 <1h 达到软上限 |
| 戴森球成本 | 1e15 稀有矿物 | **1e10 稀有矿物** | 1e15 按当前产出要 3 亿年，根本不可达 |
| v2 新增建筑 | 无 | 戴森球骨架（500 稀有矿物/s，最多 10 座） | 让戴森球在第 16 次通关后 22h 可达成 |
| 数字上限 | 未定义 | v2 最大 1e12，远在 break_infinity 安全区（1e308） | UI 用 K/M/B/T/aa/ab 标准缩写 |
| 转生软上限 | 未定义 | 第 16 次转生（之后单轮 <1h，边际收益趋零） | 防止无限转生 |

## 4. 支撑 500h 的机制清单

### 4.1 转生循环（Prestige）
- 解锁：第一次火箭升空后。
- 每次通关给星尘，每点星尘 **+10% 全局产出（加法）**。
- 第 N 轮主线时长：T(N) = 18 / (1 + 0.10×(N-1)(N+14)/2)。
- 第 16 轮后单轮 <1h，软上限。
- v1 只留 schema 字段（`meta.prestigeCount / meta.globalMult / meta.prestigeHistory`），v2 填实。

### 4.2 图鉴系统（Codex）
- 200 项：36 建筑皮肤 + 24 小人服装 + 6 奇观 + 20 遗物 + 其他。
- 解锁方式：业务代码发事件（`building:built` / `worker:recruited` / `resource:gained`），图鉴 store 订阅规则表。
- 老存档迁移时快照补漏。
- v1 只建事件总线和空表，v2 填内容。

### 4.3 成就系统
- v1 冻结 12 个（见 04a §6.4）。
- v2 扩到 50 个，分 5 类：通关 / 收集 / 操作 / 挂机 / 隐藏。
- 不奖励数值，只奖励图标和 itch.io 页面展示。

### 4.4 世界种子
- v1 做软种子：影响地图布局和初始小人名，不影响数值期望。
- 10 个精选种子作为"推荐重开"。
- v2 加种子竞速（同 seed 比谁先到小镇）。

### 4.5 挑战模式
- v1 只做"铁人模式"开关（关闭离线收益）。
- v2.5 做每日挑战（UTC 日期 + 盐生成种子，30 天滚动存档）。
- v3 做种子竞速排行榜（需要后端）。

## 5. v1 / v2 / v3 边界

| 版本 | 内容 | 累计时长 |
| --- | --- | --- |
| **v1（itch.io 首版，M0-M3）** | 主线前 3 阶段（原始/村庄/小镇）+ 12 成就 + 世界种子 + 铁人模式 | ~1h 教学关 |
| **v1.5（M4）** | 主线后 3 阶段（城市/国家/太空）+ 火箭升空 | ~18h 主线 |
| **v2（M5 + 后续）** | 戴森球 + 星尘 Prestige + 图鉴骨架 + 成就扩到 50 | ~150h |
| **v2.5** | 每日挑战 + 图鉴填满 200 项 | ~250h |
| **v3** | 种子竞速排行榜 + 全成就 + 全图鉴 | ~500h |

**关键**：v1 上线 itch.io 时只承诺"18h 主线"，不承诺 500h。500h 是 v3 的目标，不是 v1 的验收标准。

## 6. 对 M0 的影响（明天开工要不要改计划）

**结论：M0 第一天工作量不变，但 v1 存档 schema 必须一次预留以下空字段（30 分钟工作量）：**

```ts
interface MetaState {
  prestigeCount: number;        // v1 = 0
  globalMult: number;            // v1 = 1
  prestigeHistory: PrestigeEntry[];  // v1 = []
  codex: Record<string, boolean>;    // v1 = {}
  achievements: Record<string, boolean>;  // v1 只填前 12 个
  lifetimeStats: { totalPlaytime: number; totalWorkers: number; ... };
  seedHistory: number[];         // v1 = []
  dailyHistory: Record<string, boolean>;  // v1 = {}
  debugUsed: boolean;            // debug 档不污染 meta
}
```

其他架构调整：
- M1 建 meta slice；
- M2 注入 RNG + globalMult 参数；
- M3 事件总线补全 + 成就/图鉴骨架；
- M4 存档体积监控（>1MB 报警）；
- M5 Prestige 填实。

**不需要推翻任何已确认架构**。

## 7. 性能与存档大小预估

| 项 | 预估 |
| --- | --- |
| 500h 后主线存档 | ~53 KB |
| 每日挑战 30 天滚动 | ~600 KB |
| 合计 | ~650 KB |
| localStorage 上限 | 5 MB |
| 结论 | **完全够，不需要 v1 迁 IndexedDB** |

迁 IndexedDB 的触发条件（v2 才考虑）：
- 主线存档 > 1 MB；
- 或浏览器抛 `QuotaExceededError`；
- 或 500h 玩家实测存档膨胀超预期。

`seenWorkerNames` 硬上限 500 防膨胀；`prestigeHistory` 只留 50 轮摘要（200B/轮）。

## 8. QA 怎么测 500h 内容

- ×10000 倍速冒烟：3 分钟跑通一周目。
- ×1000 倍速跑 3 次 Prestige：1.5h。
- 全成就/图鉴回归：50 分钟。
- 人测只在 1h / 10h / 100h 三个时间点抽样。
- 倍速必须走 `clock.now()` 不走 rAF；debug 档 `meta.debugUsed=true` 不污染 meta；给资源 clamp 到 1e200 防 break_infinity 溢出。
