# 05. 资源点可采空与自动刷新设计

> 2026-09-18 用户提出：资源应该可以采集完，但会自动刷新。
> 状态：已采纳，排期 M2（与食物系统同期实现）。数值均为推荐默认值，可调。

## 1. 核心规则

1. 每个资源点有**储量上限**（capacity）与**当前剩余量**（remaining）。
2. 工人每采 1 次，对应资源点 remaining -1。
3. remaining 降至 0 → 资源点**采空**：不可再采，视觉变灰/枯萎。
4. 采空后进入**刷新倒计时**（respawnAt），到点后 remaining 回满 = capacity。
5. 刷新是自动的，玩家无需操作。

## 2. 数值默认值（04c 草案补充，可调）

| 资源点 | 容量 capacity | 刷新周期（采空→回满） |
| --- | --- | --- |
| 浆果丛 | 20 | 120s |
| 树林 | 15 | 180s |
| 石堆 | 10 | 240s |

> 刷新周期含"离线时长"（见 §6）。容量与周期是 M2 可玩性调参点。

## 3. 工人行为

1. 出发前检查目标资源点 `remaining > 0`；为 0 则**换点**（优先去当前剩余量最多的点，均衡考虑距离）。
2. 所有资源点均采空 → 工人回山洞 idle（消息"资源采空了"），每 2s 重查一次，任一刷新即自动恢复。
3. 与食物系统优先级：先判"饿不饿"（食物耗尽→罢工），再判"资源点有没有货"。两套机制独立，不互斥叠加。

## 4. 视觉表现

| 状态 | 表现 |
| --- | --- |
| 正常 | 现有圆点颜色 |
| 采空 | 圆点变灰 + 缩放变小，标签保留（可加"（空）"） |
| 刷新完成 | 恢复原色原尺寸 |

## 6. 离线结算口径（关键，需实现时定稿）

- **离线速度系数**：离线产出 = 在线速率 × 0.2（用户 2026-09-18 拍板，ADR 023，替代原阶段效率系数）。
- **资源点刷新计时**：离线时长计入刷新倒计时（respawnAt 按真实时间流逝）。
- **离线产出上限**：离线收益 = min(速率 × 0.2 × 秒, 资源点剩余总量)，即离线不能突破储量上限。
- 实现建议：离线结算后把 remaining 同步扣减；若结算中某点被采空，按刷新周期回满（简化：逐点结算）。
