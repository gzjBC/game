## 1. 四方已经达成的共识（不用再讨论）

这些点四个角色在各自文档里口径一致，直接冻结：

1. **六阶段弧线不动**：原始 → 村庄 → 小镇 → 城市 → 国家 → 太空。首版（itch.io）只做到小镇，后三阶段在 M4/M5 补。
2. **三层架构铁律不动**：`game/` 纯逻辑不 import React/Phaser；`scene/` 不 import React；`ui/` 不 import Phaser。
3. **离线结算走双时间源**：在线用 rAF 固定步长 accumulator；离线用 `clock.now() - lastSavedAt` wall-clock。**两条通道共用同一份 `computeProductionRatePerSecond` 纯函数**——QA 的 F4 用例是硬要求。
4. **离线收益有阶段化 cap 和效率系数**：不是白送。v1 总上限 8 小时（对齐 ADR 004），阶段效率系数 `[0.25, 0.40, 0.60, 0.75, 0.90, 1.00]`。
5. **小人不真做 8 小时寻路**：离线结算时所有小人 state 重置为 idle、x/y 重置到家，只结算资源，不模拟动画。
6. **v1 不防作弊**：localStorage 可改，单机 itch.io 作品不值得反作弊；v2 接后端后服务端时间戳校验。
7. **大数字用 break_infinity.js**，但**不把 BigNumber 直接塞进 zustand**（引用比较会导致 React 每帧重渲染）——存 string/exponent，渲染时再 `new BigNumber(x)`。
8. **随机数必须走注入 RNG**（mulberry32 + 种子），**禁止裸 `Math.random()`**——否则世界种子/测试全崩。ESLint 规则 v1 就开。
9. **存档 schema v1 就分两层**：`meta`（成就、prestigeCount、皮肤、星尘）和 `run`（本次资源/建筑/小人）。为将来转生留路，v1 不加这层以后要迁移老存档。
10. **debug 倍速模式 M2 前必须落地**：`?debug=1` + `setMultiplier/setTimeScale/give/unlockStage`，×1000 倍速把 18h 主线压到 ~2 分钟。这是 P0 阻塞项，不然后续每次回归 QA 都要坐 2 小时。
11. **小人不死**：饿肚子只罢工/减速，不消失；50 年（现实 1 周）后自动退休走出画面，换新。
12. **不做战斗系统**：纯经营，用随机事件制造张力。
13. **v1 科技树纯线性**，JSON schema 预留 `branch` 字段，分支留到 v2。
14. **v1 不做多语言、不做付费、不做云存档**；导出存档为 JSON 下载作为备份。

## 2. 真正的分歧 / 需要用户拍板的事项

> 每条都标了：各方立场、Organizer 推荐、风险。**用户看完直接选 A/B/C 即可，不用再开会。**

### 2.1【关键】主线通关线画在哪？戴森球算不算 v1 内容？

| 立场 | 谁主张 | 内容 |
| --- | --- | --- |
| A. 主线通关 = 火箭升空；戴森球是 v2 终局 | 数值策划（强推）、程序架构、QA | 戴森球要 1e15 稀有矿物，按当前产出 ≈ 3 亿年，单次主线根本不可达 |
| B. 主线通关 = 戴森球建成；火箭只是中点 | 主策划初稿 | 视觉高潮放在戴森球 |

**Organizer 推荐：A。** 理由：B 数值上不成立，硬做要么把戴森球成本砍到 1e12（数值策划附录里也标了"可能压"），要么玩家永远看不到结尾。v1 主线画在"火箭升空 + 30 秒过场"，戴森球作为 v2 Prestige 倍率下的终局目标。

### 2.2【关键】Prestige 转生 v1 做不做？

| 立场 | 谁主张 | 内容 |
| --- | --- | --- |
| A. v1 不做，v2 上线"新文明"硬转生（清空资源，×1.5 永久加成） | 主策划 | 仪式感强，不污染 v1 开发量 |
| B. v1 就做"星尘"软转生（不清档，通关累积星尘，每点 +10% 全局倍率） | 数值策划、QA | 不做硬重置，只给永久加成字段；成本极低 |
| C. v1 只留 schema 字段，数值和 UI 都不做 | 程序架构 | 最省 |

**Organizer 推荐：B + C 合并**——v1 只做"通关后给星尘、星尘提供全局倍率"这一最小闭环（< 3 人天），不做"清空重来"的硬转生。理由：挂机游戏没有任何永久加成，朋友试玩通关一次就再也不会打开；而硬转生的 UI/教程/存档迁移成本不值 v1 投入。硬转生推到 v2。

### 2.3 星尘加成是加法还是乘法？

QA 抛出的点：
- 加法：每点星尘 +10% 全局产出（10 点 = ×2.0）
- 乘法：每点星尘 ×1.1（10 点 = ×2.59）

**Organizer 推荐：加法**。理由：挂机游戏数值设计怕指数叠加失控；加法玩家可预期、QA 好测。三次通关后约 ×1.5，和主策划"二周目 7 小时"的目标对齐。

### 2.4 总通关时长口径统一

三方数字看似打架，其实是同一件事的不同切面，统一为：

| 玩家类型 | 现实日历通关时间 | 纯在线操作时间 |
| --- | --- | --- |
| 爆肝（每次上线点满） | ~5-7 小时 | ~5-7 小时 |
| 正常上班族（每天 2-3 次，每次 10-15 分钟） | **~10 小时** | ~3 小时 |
| 每天挂 8h 共 3 天 | ~3 天 | ~18 小时 |
| 24h 挂机不操作 | 5-7 天 | ~18 小时 |

**这个数字不需要用户拍板**，但要写进 README 和 itch.io 页面，避免朋友试玩时预期错位。

### 2.5 灾害 / 随机事件做不做？

| 立场 | 内容 |
| --- | --- |
| A. v1 完全不做 | 最省 |
| B. v1 做轻度 buff/debuff 事件（丰收/商队），不破坏建筑 | 主策划推荐 |
| C. v1 做完整灾害（火灾/瘟疫，会毁建筑） | 不推荐 |

**Organizer 推荐：A 推到 v2**。理由：v1 要做的是把"小人干活"核心爽点打磨好，随机事件系统至少 1-2 周，首版不值。v1 用"阶段跃迁演出 + 成就 toast"已经够有变化感。

### 2.6 商业模式

主策划推荐 itch.io 一次性 $5-8，无广告无内购。
**Organizer 推荐：v1 先免费上 itch.io 拿反馈，M3 上线时再决定是否付费**。理由：作品集阶段最重要的是"有朋友真的点开玩"，付费门槛会把试玩人数砍一个数量级。

### 2.7 技术细节 5 项（程序架构师提出）

| # | 事项 | 推荐 |
| --- | --- | --- |
| 1 | 是否新建 `game/events/bus.ts` | **建**。Phaser 事件和 zustand subscribe 混着用会乱，统一一个 EventEmitter |

## 3. 辩论记录（谁说了什么）

### 3.1 主策划挑战其他三方

- **对程序架构**：easystarjs 必须放 game/ 纯逻辑层，可走性网格抽成 `Uint8Array`，scene/ 只负责从 Tiled JSON 转换；离线后小人状态必须重置到家；WorkerSprite 必须对象池；BigNumber 不能直接进 zustand。
- **对数值**：阶段跃迁时旧资源不能直接保留成"可花的钱"（不然阶段 4 玩家用阶段 3 攒的木材直接盖 10 个市场），建议折算成"时代点数"永久加成；食物产出必须随人口指数增长；效率堆叠要设软上限（>×3 后递减）。
- **对 QA**：小人动画不测像素，测状态机序列（idle→pathfind→arrive→work→deliver→idle）。

### 3.2 数值策划挑战其他三方

- **对主策划**：篝火不能改成产出食物（会把"5 分钟生火"压成 1 分钟）；酒馆人口 +5 必须配食物消耗；全局倍率科技上限 ×1.2，别做 ×2。
- **对程序**：`balance.ts` 必须拆目录，所有数字字段强制 `Decimal`，JSON 启动时 zod 校验 fail-fast。
- **对 QA**：戴森球 1e15 加法精度、离线时间差负数、成本递增 n=0 vs n=1、浮点累积误差、离线 cap 边界——这 6 个是必测边界。

### 3.3 程序架构师挑战其他三方

- **硬约束**：clock 必须注入（所有 `Date.now()` 走 `clock.now()`），否则离线/dt 测试写不了；Phaser.Game 不能挂 window 单例，要可 destroy；state 必须纯 JSON（不能有 Map/Set/class 实例）；action 必须 `(state, payload) -> newState` 纯函数。
- **对策划**：阶段换皮时旧 tilemap 用 scene 嵌套卸载；配置 JSON 启动时 schema 校验。
- **对 QA**：同屏 20 worker 时 60fps 是性能预算线。

### 3.4 QA 挑战其他三方

- **对策划**："前 5 分钟做什么"必须写死成第一次点击序列；离线收益上限给个数；阶段切换要提前 80% 进度预告；小人名是装饰还是剧情？
- **对程序**：clock 注入、Phaser 实例可销毁、game/ 不反向依赖、state 纯 JSON、action 纯函数——五条全是 P0。
- **对数值**：采集速率 < 寻路速率会"原地空跑"；离线乘法在 0.001/s 和 e5/s 两端都要测；资源上限要有定义。

## 4. 明天（实际开工日）的第一步

按 04b §4 的拆步，M0 第一天只做：

1. 装 Node 22（已就绪）+ 三个 VSCode 插件。
2. `npm create vite@latest high-game -- --template react-ts`。
3. 装依赖：`phaser zustand tailwindcss postcss autoprefixer easystarjs break_infinity.js`。
4. 配 Tailwind。
5. 写最小 GameScene：绿色方块每秒右移 1 像素。
6. App.tsx 里挂 Phaser，旁边放一个 React 按钮。
7. `npm run dev` 确认 HMR。
8. **验收**：左半屏绿方块在动，右半屏按钮能点，F5 不崩。

在动键盘之前，**请用户先把第 2 节的 2.1 / 2.2 / 2.3 三个关键分歧拍板**，其他都是 Organizer 推荐直接采纳，不影响 M0。
