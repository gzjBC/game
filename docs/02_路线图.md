# 《High》执行路线图 v2

> 更新日期：2026-09-19  
> 本文是当前唯一的执行计划；`04*` 系列保留为设计资料，`项目记忆.md` 保留决策与历史记录。  
> 计划原则：先做出可公开试玩、可收集反馈的版本，再扩内容纵深。

## 1. 当前基线

### 已完成

- React + TypeScript + Phaser + Zustand 的前端骨架可运行。
- 原始时代 → 村庄阶段可玩：采集、生火、招募、茅草房、仓库、制陶、火耕。
- 三类资源、10 个资源点、采空/倒计时/随机重生、建筑碰撞与寻路已接入。
- 像素小人、随机中英文名、饥饿觅食、离线收益、自动存档、存档迁移、备份与坏档留存已接入。
- Debug 倍速、世界种子与 94 条单元测试已接入。

### 2026-09-19 实测

| 项目 | 结果 | 结论 |
| --- | --- | --- |
| `npm exec vitest run` | 8 个测试文件、94/94 通过 | 逻辑基线稳定 |
| `npm run build` | 构建通过 | 可生成静态站点 |
| `npm run lint` | 1 条警告 | 发布前清零 |
| 生产包 | JS 约 1.63 MB，gzip 约 438 KB | Alpha 可接受，后续做 Phaser 分包/加载体验优化 |

### 当前缺口

1. 自动化验证仍分散为三条命令，缺少统一的发布前检查入口。
2. 首次进入没有明确目标，按钮只置灰但不解释“下一步做什么”。
3. PC 固定双栏布局，尚未完成 375×667 等移动端验收。
4. 重置缺少二次确认；坏档虽会备份，但玩家没有可见的恢复/导出入口。
5. 还没有公开试玩链接、版本号、发布清单和真实玩家反馈。
6. 小镇阶段仍停留在设计文档，若与发布强绑定会继续推迟首次上线。

## 2. 版本目标与边界

### v0.1 Alpha：先公开当前村庄纵切

玩家在 10–20 分钟内能理解并完成以下闭环：

`看见小人采集 → 生火 → 招募 → 建房/仓库 → 管理食物与容量 → 研究火耕进入村庄`

发布标准：外部玩家打开链接即可游玩，刷新不丢档，移动端不溢出，遇到坏档不会静默覆盖唯一存档。

### v0.2：补齐“小镇到达”纵切

在 v0.1 反馈证明核心循环可理解后，再加入：

- 村庄阶段的最小内容：石斧工作台、磨制石器、集市。
- `stone → village → town` 三阶段状态与存档迁移。
- 阶段跃迁横幅和场景换色；小镇先作为首版终点，不一次实现完整城市经营。
- 新档 20–30 分钟到达小镇；Debug 10x 下 3 分钟内可回归完整流程。

### 本轮明确不做

- 城市、国家、太空、戴森球和 500 小时内容。
- Prestige、道具/肉鸽、随机灾害、成就大全。
- 登录、排行榜、Postgres 云存档。
- 大规模科技树、多语言和商业化。

以上设计继续保留，但只有在公开版本获得有效反馈后才进入排期。

## 3. 里程碑

### R0：基线收口（0.5–1 天）

目标：让仓库达到“每次修改都能一条命令验证”的状态。

- [ ] 修复当前 lint 警告，`npm run lint` 零警告。
- [ ] 在 `package.json` 增加 `test` 与 `check` 脚本，统一执行 lint、测试、构建。
- [x] 用实际项目说明替换 Vite 模板 README，写清启动、测试、构建和目录。
- [ ] 给 Alpha 定版本号，并在界面或构建信息中可查。
- [ ] 固化 v2 存档回归样本：新档、旧档、坏 JSON、超容量档。

验收：全新安装后按 README 可启动；`npm run check` 一次通过；不依赖口头说明。

### R1：首玩体验与数据安全（2–3 天）

目标：没看过文档的玩家也知道下一步，误操作不会轻易丢档。

- [ ] 增加一个非强制任务提示，只显示当前最重要目标及进度。
- [ ] 不可用按钮显示缺少的资源/前置条件，而不是只置灰。
- [ ] 离线收益改为可关闭的摘要，明确离线效率和 8 小时上限。
- [ ] 重置增加二次确认；保存失败和坏档恢复给出可见提示。
- [ ] 增加存档导出/导入，导入前校验版本并保留当前档备份。
- [ ] 为生火、建造、研究和时代跃迁补齐视觉/文字反馈。

验收：3 名第一次接触项目的玩家中，至少 2 名能在不看说明的情况下完成“生火 → 招募 → 第一座房”；无一人因误点重置丢档。

### R2：移动端与可访问性（2–3 天）

目标：PC 和手机都能完成核心闭环。

- [ ] PC 保持画布 + 侧栏；窄屏改为画布在上、操作区在下。
- [ ] 画布按容器缩放，保持像素清晰，不出现横向滚动条。
- [ ] 工人列表和操作区独立滚动，主要按钮触控高度不低于 44 px。
- [ ] 检查颜色对比、焦点状态和按钮文本，关键信息不只靠颜色传达。
- [ ] 通过 375×667、390×844、768×1024、1366×768 四个断点。

验收：四个断点都能完成建房和研究；页面无横向溢出；Android Chrome 和 iOS Safari 各完成一次 5 分钟冒烟。

### R3：v0.1 Alpha 发布（1–2 天）

目标：拿到真实公开链接和反馈，而不是继续只在本地扩功能。

- [ ] 运行完整 `check`，记录包体、测试数和已知问题。
- [ ] 准备封面、3 张截图、中文简介、操作说明和隐私说明。
- [ ] 将静态构建发布到 itch.io；PWA 不作为 Alpha 阻塞项。
- [ ] 用全新浏览器配置验证首次进入、存档、刷新、离线返回与重置。
- [ ] 邀请至少 3 名玩家试玩 10–20 分钟，记录到达步骤、卡住位置和一句主观反馈。

验收：公开链接可访问；Chrome/Safari 无 P0 阻塞；3 份反馈已归档；P0 缺陷为 0。

### R4：v0.2 小镇纵切（5–8 天）

目标：在已有闭环上增加一次明确的内容跃迁，不全面铺开六阶段。

- [ ] 先冻结最小配置表：工作台、磨制石器、集市的成本和效果。
- [ ] 存档升级到 v3，新增 `town` 阶段及所需建筑/科技字段；v2 自动迁移。
- [ ] 增加工作台和磨制石器，形成“采集 → 提效 → 攒集市”的村庄循环。
- [ ] 建成集市后进入小镇，显示阶段横幅并切换地表/配色。
- [ ] 用模拟脚本和人工试玩调到新手 20–30 分钟到小镇。
- [ ] 新增阶段、迁移、边界和离线结算测试，保持全量测试通过。

验收：新档可无作弊到达小镇；旧 v2 档不丢资源；10x Debug 3 分钟内走通；至少 3 名玩家中 2 名愿意玩到阶段跃迁。

### R5：根据反馈决定下一阶段（评审门）

只有在 v0.2 达到以下信号后，才选择“继续内容”或“做全栈化”：

- 5 名有效试玩者中至少 3 名到达小镇。
- 没有重复出现的 P0/P1 存档问题。
- 玩家能复述核心循环，并明确指出一个最想继续玩的方向。

可能路线：

1. 若玩家想要更多经营深度：先做可分配工作、工具生产和小镇建筑。
2. 若作品集后端价值更高：做最小账号 + 云存档，不同时做排行榜。
3. 若留存弱：先改前 10 分钟反馈与节奏，不扩城市/太空内容。

## 4. 优先级队列

### P0：下一批必须完成

1. 质量命令与 lint 清零。
2. 首玩目标提示和按钮缺口提示。
3. 重置确认、存档导出/导入、坏档可见提示。
4. 375×667 响应式闭环。
5. itch.io Alpha 发布与 3 人试玩。

### P1：Alpha 后立即评估

1. 小镇最小配置冻结。
2. v3 存档迁移与 `town` 阶段。
3. 工作台、磨制石器、集市、阶段演出。
4. 20–30 分钟节奏实测。

### P2：有数据再做

1. Phaser 动态加载/代码分包与首屏加载优化。
2. PWA、离线安装和更完整的音效/美术。
3. 成就、图鉴、道具、转生、后端与后续时代。

## 5. 每次发布的统一门禁

| 维度 | 必须满足 |
| --- | --- |
| 自动化 | lint 0 警告；测试全绿；生产构建通过 |
| 数据 | 新档、旧档、坏档、导入失败均不会静默覆盖唯一存档 |
| 功能 | 从新档走通当版主线；离线返回和刷新不重复结算 |
| 兼容 | Chrome 桌面 + Android Chrome + iOS Safari 冒烟通过 |
| 响应式 | 375×667 无横向滚动，关键按钮可触达 |
| 性能 | PC 10 人场景无明显卡顿；记录 5 分钟内存与帧率观察 |
| 文档 | README、版本号、变更记录、已知问题与实际实现一致 |

## 6. 建议节奏（每周 10–15 小时）

| 周次 | 交付物 |
| --- | --- |
| 第 1 周 | R0 + R1：质量收口、首玩引导、数据安全 |
| 第 2 周 | R2 + R3：移动端、公开 Alpha、3 人反馈 |
| 第 3 周 | R4 前半：小镇配置、v3 存档、村庄内容 |
| 第 4 周 | R4 后半：阶段演出、平衡、v0.2 发布 |

时间预算是上限，不是承诺；单项超时 50% 时必须砍范围或拆分发布，不顺延整个版本。

## 7. 计划维护规则

- 完成项必须同时附验收证据，例如测试结果、截图、公开链接或试玩记录。
- 新需求先进入 P2，不直接插进当前里程碑；只有 P0 缺陷可打断当前工作。
- `项目记忆.md` 记录“为什么这样决定”，本文件只记录“现在做什么、做到什么算完成”。
- 每次发布后更新基线数字、已知问题和下一评审门，避免文档再次落后于代码。
