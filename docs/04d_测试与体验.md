# 《High》测试与体验方案（QA / 可测性设计 v1）

> 2026-09-17 · QA 负责人 + 小白玩家视角。本文是纯规划文档，配合 `测试组/测试计划.md` 使用：那份是总纲，这份是落到模块、用例、预算、验收细节的执行版。
> 原则：**game/ 纯逻辑 100% 可在 Node 里单测；凡是依赖 `Date.now()`、`localStorage`、`window`、Phaser 的地方，全部通过"注入"暴露成可替换的边界。**

---

## 1. 测试金字塔与策略

### 1.1 金字塔形状（本项目的现实比例）

```
        /\          E2E（Playwright）  → v1 不上，理由见 1.5
       /  \         手动探索 / 体验    → 20%（画面、手感、手机、引导）
      /----\        集成测试          → 30%（React+Phaser 挂载、zustand action 串联）
     /------\       单元测试          → 50%（game/ 纯逻辑，Vitest，必须 Node 直跑）
```

**为什么单元层占比最大**：挂机游戏的 bug 90% 是"时间差算错 / 数字溢出 / 状态机跳变 / 迁移丢字段"——这些全是纯逻辑，不需要浏览器就能测，跑得快、能进 CI。画面层的 bug 少且必须人眼看，不能硬凑自动化比例。

### 1.2 单元测试覆盖的 game/ 模块清单

| 模块 | 职责 | 必须覆盖的边界 |
| --- | --- | --- |
| `offline.ts` | 离线收益结算（时间差算法） | 0 秒 / 负数 / 超长 / 期间建筑被拆 / 上限截断 |
| `production.ts` | 每帧产出推进 | dt 抖动 / dt=0 / dt 负数 / dt 巨大 |
| `save.ts` | localStorage 读写 + 版本迁移 | v0→v1 / 字段缺失 / JSON 损坏 / 配额满 |
| `nameGenerator.ts` | 小人名 / 地名生成 | 重名概率 / 音译表缺失 / 并发生成 |
| `bigNumber.ts` | break_infinity.js 封装层 | 边界、序列化、减法变负、乘法溢出到 e308+ |
| `resource.ts` | 资源池加减 / 上限 | 减到 0 不再负 / 大数比较 |
| `building.ts` | 建造 / 升级 / 拆除 | 钱不够 / 连点 / 拆一半正在建造的 |
| `villager.ts` | 小人状态机（空闲/采集/赶路/休息） | 状态跳转非法 / 目标消失 / 寻路失败 |
| `techTree.ts` | 科技解锁 | 前置未点 / 重复点 / 花光资源 |
| `stage.ts` | 六阶段切换判定 | 门槛临界 / 跨阶段旧建筑残留 |
| `clock.ts` | **时钟抽象（必建）** | 可注入假时钟，所有 `Date.now()` 走这里 |

### 1.3 重点模块 Given-When-Then 用例

> 表中"时钟注入"指：测试里传一个可控的 `now()` 函数，不依赖真实系统时间。

#### A. offline.ts（离线结算）

| # | Given | When | Then |
| --- | --- | --- | --- |
| A1 | 存档 lastSaved = T；当前时钟 = T | 调用 calcOffline(T, T) | 离线秒数 = 0，收益 = 0，**不弹结算弹窗** |
| A2 | 存档 lastSaved = T+3600（系统时间被回拨） | 调用 calcOffline(now=T, lastSaved=T+3600) | 离线秒数 = 0 或取 min(0, diff)，**不得结算出负收益**，不崩 |
| A3 | lastSaved = T；now = T + 100×24×3600 | 结算 | 收益按"离线收益上限"截断（如 8 小时），不得按 100 天全算 |
| A4 | 离线期间某建筑已被玩家拆除（v0 有该建筑，v1 无） | 结算 | 只按"当前存档中仍存在的建筑速率"结算，不引用已拆建筑 |
| A5 | 离线收益为大数（break_infinity e300+） | 结算 + 写档 | 不出现 `Infinity`、`-Infinity`、`NaN`，刷新后数字可读 |
| A6 | 时钟源被 mock 成"快进 1 小时" | 连续结算两次 | 第二次以第一次结算后的 lastSaved 为起点，**不得重复发钱** |

#### B. production.ts（每帧推进）

| # | Given | When | Then |
| --- | --- | --- | --- |
| B1 | tab 切走 10 分钟回来，Phaser 给的 dt = 600s | 单帧 tick(dt=600) | 产出按 600s 结算一次，**不得卡成多帧连跑**，帧率恢复正常 |
| B2 | dt = 0 | tick(0) | 产出增量 = 0，状态机不跳变，不抛异常 |
| B3 | dt = -0.5（时钟回拨） | tick(-0.5) | 按 0 处理或直接跳过本帧，资源不变负 |
| B4 | dt 正常 0.016 | tick(0.016) | 产出精确累加；连续 tick 1000 次 ≈ 16s 总产出，误差 < 1e-6 |
| B5 | 资源已达上限 | tick(持续产出) | 到顶即停，不溢出成 NaN，UI 显示"已满" |

#### C. save.ts（存档）

| # | Given | When | Then |
| --- | --- | --- | --- |
| C1 | localStorage 里是 v0 存档（无 version 字段） | load() | 自动迁移为 v1，旧资源/建筑保留，不丢档 |
| C2 | v1 存档但缺 `villagers[3].state` 字段 | load() | 缺失字段用默认值兜底，不抛 undefined |
| C3 | localStorage 里被改成 `{{{ 坏 JSON` | load() | 捕获 parse 异常，进入"坏档恢复"分支，提示用户而非白屏 |
| C4 | localStorage 已写满 ~5MB（QuotaExceededError） | save() | 捕获异常，UI 提示"存档失败，请清理浏览器数据"，游戏不崩 |
| C5 | 连续快速 save 20 次（连点 F5 / 连点按钮） | — | 不出现中间态坏档；至少最后一次成功 |
| C6 | 版本号 v99（未来版本） | load() | 拒绝降级加载，提示"存档来自更新版本"，给"清除存档"入口 |

#### D. nameGenerator.ts（命名）

| # | Given | When | Then |
| --- | --- | --- |
| D1 | 已用名集合 = 空 | 生成 1000 个名字 | 重名率 < 1%（同屏 50 个小人时肉眼无重复感） |
| D2 | 音译表（拼音→汉字）文件缺了某个音 | 生成到该音 | 回退到通用字表，不报错不卡死 |
| D3 | 并发生成 1000 个名字 | — | 全部唯一或按策略去重；耗时 < 50ms |
| D4 | 已有 99 个小人，池子快用完 | 再生成 1 个 | 进入"重名加序号"兜底（小明、小明2），不崩 |
| D5 | 输入边界：长度限制 2~6 字 | 极端 seed | 不生成空字符串 / 超长串 / 表情乱码 |

#### E. break_infinity.js 大数边界（封装层 bigNumber.ts）

| # | Given | When | Then |
| --- | --- | --- | --- |
| E1 | a = e300，b = e300 | a + b | = e300×2，不溢出成 Infinity |
| E2 | a = e100，b = e50 | a - b | ≈ a（小的被吸收），**不得出现负数** |
| E3 | a = e5，b = e-5 | a × b | = e0 = 1，精度不丢 |
| E4 | 任意大数 | JSON.stringify → JSON.parse | 反序列化后值与原数误差可忽略（break_infinity 序列化是高频翻车点，见 §5） |
| E5 | 显示层 | 数字 = e1500 | 格式化为 "1.5e1500" 或可读缩写，UI 不爆宽度 |

### 1.4 集成测试（Vitest + jsdom / happy-dom，不启真浏览器）

| # | 场景 | 断言 |
| --- | --- | --- |
| I1 | React 面板 + Phaser 画布在 jsdom 挂载 | 无报错；zustand store 初始态正确 |
| I2 | 点击"建造浆果采集点"action → store 更新 → UI 数字刷新 | 资源扣减、建筑列表新增、Phaser 场景出现建筑精灵，三者一致 |
| I3 | 关闭页面再 load() → 重建 store → 画面恢复 | 资源、建筑、小人位置与关页前一致 |
| I4 | 离线结算 action → store 更新 → 弹窗组件渲染 | 弹窗金额 = calcOffline 的返回值，不是两套数 |
| I5 | 时钟快进 1 小时（注入假时钟）→ tick → save | 全链路数字闭环：产出 = 花费，无悬空 |

### 1.5 手动测试（必须人测，自动化测不了）

- **手感**：同屏 50 个小人跑来跑去，画面卡不卡、动画顺不顺眼。
- **离线收益弹窗观感**：数字滚动动画舒不舒服，关不掉怎么办，点"开心收下"后资源数字有没有跳变。
- **手机浏览器**：iOS Safari / Android Chrome 各走一遍主线。
- **响应式断点视觉**：有没有元素压字、按钮点不到。
- **新手引导**：前 5 分钟不看文档能不能玩下去。

### 1.6 E2E 要不要上 Playwright？—— v1 不上，理由写死

1. **投入产出比差**：挂机游戏核心逻辑全是纯时间差/数字，单测已经覆盖；E2E 能测的"点按钮出数字"在集成测试 I2/I3 已经覆盖。
2. **Phaser 画布截图断言脆**：像素风动画每帧都变，容易误报，维护成本高。
3. **时间差游戏跑 E2E 需要 mock 时钟**，等于把 E2E 当集成测试写，没必要。
4. **v2 再说**：等 M3 itch.io 上线后，如果真有"用户报告线上 bug 我这边复现不出来"的情况，再只针对"打开页面→5 分钟不白屏"这条冒烟链路加一条 Playwright。

## 2. 横切质量方案

### 2.1 防作弊（v1 范围：承认防不住，只列清楚）

**v1 现实**：纯前端 + localStorage，理论上**所有存档都能被 F12 改**。v1 不假装能防，只做"不教坏玩家 + v2 留好接口"。

已知漏洞清单（写进文档，让数值和策划心里有数）：

- [ ] F12 → Application → localStorage 直接改资源数 → 立刻生效。
- [ ] 改系统时间往前刷离线收益（改完再改回来）。
- [ ] 删 localStorage 文件 → 回到初始档（等于"重开"，不影响别人）。
- [ ] 手动往 localStorage 写超大数字 → UI 显示爆炸。
- [ ] DevTools 里直接 dispatch zustand action。

**v1 要做的"最低限度"**：

- 离线收益**硬性上限**（如现实 8 小时封顶），改时间刷不到天上去。
- 数字合法性校验：加载存档时，资源 > 某阶段理论上限就 clamp 或警告。
- **不做**：hash 校验存档（前端 hash 一样能被改，白费）。

**v2 服务端校验接口预留**（现在就把 game/ 模块写成"可纯函数"，将来直接搬到 Node 后端复算）：

- `POST /api/offline-settle`：服务端拿 `(lastServerTick, serverNow, buildState)` 重算，不信客户端数字。
- `POST /api/save`：服务端校验 `资源 > f(阶段, 在线时长)` 时拒绝或 clamp。
- 现在 game/ 里凡是"数字从哪来"的函数，签名都要保持 `(state, input) -> newState`，不偷偷读全局。

### 2.2 性能预算

| 平台 | 同屏小人目标 | 帧率目标 | 备注 |
| --- | --- | --- | --- |
| PC Chrome（中端） | 100 个 | 60 FPS | Phaser 每帧 < 16ms，目标 < 8ms |
| 手机 Android 中端 | 30 个 | 60 FPS | |
| 手机低端 / iOS 老款 | 30 个 | **30 FPS 可接受** | 挂机类不是动作游戏，掉帧到 30 可玩，但不能低于 24 |
| iPad | 60 个 | 60 FPS | |

**性能回归测试方法（每次里程碑跑一次）**：

1. 跑到指定小人数量（如 PC 100 个）。
2. F12 → Performance → 录 5 秒。
3. 看 Main thread 每帧耗时：> 16ms 的帧占比 < 5% 算过。
4. 看 Phaser 渲染调用：有没有同屏重复 draw call（合批问题）。
5. 看 Memory：玩 10 分钟后堆能不能回落（Phaser sprite 泄漏是高频坑）。
6. 把数字记在里程碑 checklist 里，**不写"感觉不卡"**。

### 2.3 响应式测试矩阵

| 断点 | 必须测的事 |
| --- | --- |
| PC 1920×1080 | 三栏布局（左资源 / 中地图 / 右面板）不挤压；数字不换行 |
| PC 1366×768 | 同上，最窄 PC，右面板按钮是否被挤掉 |
| 手机 375×667 竖屏 | 地图全屏在上，资源条吸顶，底部操作条可点；不出现横向滚动条 |
| 手机横屏 | 地图和面板是否变成左右分栏；虚拟键盘弹起时不遮挡按钮 |
| iPad 768×1024 | 介于手机和 PC 之间，不出现"两套样式打架" |

每个断点至少过 4 件事：**①能进游戏 ②能建一个东西 ③能开一个面板 ④数字不溢出屏幕**。

### 2.4 存档健壮性

- 存档 JSON 顶层必须有 `"version": 1` 字段，`save.ts` 每次读写必带。
- 坏档恢复按钮：load 失败时，首页给两个按钮——**"尝试继续（只读坏档预览）"** 和 **"清除存档重开"**。
- "清除存档"入口：设置页最底部，红色，二次确认弹窗。
- 自动存档频率：建议每 10 秒 + 每次重大 action 后；**写之前先写临时 key，成功后再原子替换主 key**（防止写到一半崩了主 key 变空）。

## 3. 小白玩家体验检查表（前 5 分钟）

> 视角：一个从没玩过挂机/放置游戏的人，第一次打开《High》。他不知道"浆果"是什么、不知道"离线收益"是什么、甚至不知道为什么屏幕上有个小人在乱跑。

### 3.1 第一次打开应该看到什么

- [ ] 画面中央是一小块空地 + 2 个方块小人，资源栏显示"浆果 0"。
- [ ] 一个**带气泡的高亮按钮**："点击采集浆果"，指向空地旁的浆果丛。
- [ ] 没有任何弹窗让他选"新游戏 / 读档 / 设置"——直接进，菜单藏在右上角齿轮。
- [ ] 没有"欢迎来到石器时代"这种长文字。第一句引导 ≤ 12 个字。

### 3.2 玩家不知道"浆果怎么采"怎么办

- [ ] 浆果丛本身可点，点了直接出"采集"气泡，不强制走菜单。
- [ ] 5 秒没操作 → 气泡自动指向可点的东西；10 秒还没点 → 小人自己跑过去采一次（演示一次）。
- [ ] 引导**不锁操作**：他想乱点别的也可以，引导只是飘着，不是强制教程。

### 3.3 第一次离线结算弹窗怎么展示

- [ ] 弹窗第一行大字："你离开了 1 小时 20 分钟"。
- [ ] 第二行："期间小人帮你采到了 **XX 浆果**、**YY 木头**"——数字用绿色，从 0 滚动到目标值。
- [ ] 第三行小字："离线收益有上限，超过 8 小时不再增加"（**第一次说清楚，以后弹窗里不重复**）。
- [ ] 一个按钮："开心收下"（或"继续"）。**不做"看广告翻倍"这种 v1 不该有的东西**。
- [ ] 点收下前，世界先"暂停"在原地；点完才恢复 tick。

### 3.4 哪些按钮在不该可点的时候必须置灰

- [ ] 钱不够的升级按钮：置灰 + 飘字"还差 XX"，不是能点了再弹错误。
- [ ] 前置科技没解锁的建筑：置灰 + tooltip 说"需要先点 XX 科技"。
- [ ] 正在建造中的建筑：建造按钮置灰，显示进度条。
- [ ] 离线结算弹窗未关闭时：世界按钮全部不响应。
- [ ] 存档正在写入时："清除存档"按钮置灰（防止写到一半被清）。

## 5. Bug 预检清单（写代码前就该防的坑）

> 挂机/放置类游戏社区高频翻车点 + 本项目技术栈特有坑。**每一条都对应上面的用例或 checklist。**

1. **浏览器后台定时器冻结**：tab 切走后 `setInterval` 被 throttle 到 1 次/秒甚至更慢。对策：不要靠定时器累积 delta，靠"帧回调里的真实 wall-clock 差"，回来一次性结算（见 B1）。
2. **改系统时间刷离线**：见 A2/A6，离线秒数必须 clamp 到 [0, 上限]。
3. **localStorage 5MB 上限**：玩到后期建筑+小人+日志轻松超。对策：存档只存"派生不出来的状态"，日志/聊天这种可重建的不进存档；满了走 C4 分支。
4. **Phaser 在 iOS Safari 缩放模糊**：像素风游戏如果 scale 模式配错，Retina 屏上会糊。对策：Phaser config 里 `pixelArt: true` + `resolution: devicePixelRatio`，M3 真机过一遍。
5. **break_infinity.js 序列化丢失**：直接 `JSON.stringify(Decimal)` 经常只存下 `{mantissa, exponent}`，反序列化后原型链没了，方法丢失。对策：存档时统一 `.toString()`，读档时 `new Decimal(str)`（见 E4）。
6. **React 18 并发 + zustand 异步 action 竞态**：连点"建造"按钮，两个 async action 都读到旧 state，结果只扣一次钱但建了两个。对策：action 内部用 zustand 的 `get()` 最新值再 `set()`，不要闭包捕获旧 state；连点加锁。
7. **dt 负数 / dt 巨大**：见 B1/B3，所有 tick 入口先 `dt = clamp(dt, 0, 1)`。
8. **localStorage 写入中途崩溃**：主 key 写一半变空。对策：先写 `save.tmp`，`try { ls.setItem('save', tmp) } catch {}`，成功后再 rename（见 2.4）。
9. **寻路失败小人卡死**：easystarjs 偶尔返回 null（目标被堵）。对策：返回 null 时小人走"回家"状态，不原地抖。
10. **数字比较用 === 误判**：大数比较必须用 Decimal 的 `.gte()`，不能 `a > b`（对象引用比较恒 false）。
11. **音频/视频自动播放被浏览器拦**：M3 上线后加 BGM 时，首次没交互就 play 会被拦。对策：第一次点击后再 resume AudioContext。
12. **浮点数累加误差**：浆果 +1 +1 +1 累计 1000 次后变成 999.99999。对策：资源用整数或 break_infinity，不用裸 float。
13. **F5 刷新时 Phaser 还在 tick，store 已卸载**：刷新瞬间报错。对策：Phaser scene 的 `init` 从 store 读初始值，`shutdown` 时把 tick 停掉。
14. **viewport 高度 100vh 在手机上被地址栏撑爆**：用 `100dvh`，不用 `100vh`。
15. **存档里塞了函数/Phaser 对象**：JSON 序列化会静默丢。对策：game/ 层的 state 必须是纯 JSON 可序列化对象，Phaser 精灵不进 store。

- **阶段门槛**：阶段 N → N+1 需要的资源，是不是玩家"睡一觉"刚好能到？这个数我会拿 A 系列用例反推。
- **资源上限**：每种资源有没有上限？到了之后 UI 显示什么？没定我就按"无上限，但 break_infinity e308 截断"处理。

## 7. 议题追加：通关时长设计（QA 视角）

> 与 `04c_数值草案.md` 对齐：v1 纯活跃 18h（新手）+ 挂 3 晚 = 通关；终极目标"戴森球 1e15 稀有矿物"。v1 不做硬 Prestige，只有"星尘"软转生。

### 7.1 通关怎么定义

| 层级 | 定义 | 玩家感知 | 测试意义 |
| --- | --- | --- | --- |
| **主线通关** | 建成戴森球（太空阶段终点） | "我玩完了一遍" | 必测：从 0 到戴森球全链路无死档 |
| **阶段通关** | 完成 M1~M5 + 太空每个阶段的关键建筑 | "我又升级了" | 每阶段是一个回归 checkpoint |
| **终局内容** | 星尘累积、成就、每日挑战、流派试错 | "我还想再玩一轮" | v1 轻量做，见 §8 |

**QA 立场**：v1 只要"主线通关"这条链路必须 100% 可走通；终局内容做多少算多少，不阻塞 M5 验收。

### 7.2 压缩测试模式（debug 控制台）—— 必须有

**为什么必须有**：活跃 18h × 手动点 = 一个里程碑回归要坐 2 小时。没有倍速，QA 自己都测不完，更别提改个 bug 跑全量回归。

**推荐形态**（写进代码规范，M2 之前落地）：

- 打开方式：URL 加 `?debug=1` 或在 console 里 `window.HIGH.debug.speed(1000)`。
- 提供三件套：
  1. **产出倍率**：`setMultiplier(n)`——所有资源产出 ×n，不影响 dt、不影响离线算法。
  2. **时间倍速**：`setTimeScale(n)`——内部时钟走 n 倍，`Date.now()` 由我们的 `clock.ts` 接管（这也是 §6.2 要求注入时钟的第二个理由）。
  3. **直接给钱**：`give(resource, amount)` / `unlockStage(n)`——跳过 grind 直接测关键节点。
- **硬性约束**：
  - debug 模式写死 `?debug=1` 才生效，打包发布版不带这个入口。
  - debug 下产生的存档**不允许同步到服务端**（v2 接后端时，请求头带 `?debug=1` 直接拒）。
  - 倍速上限 ×10000，防止 break_infinity 瞬间爆到 e308。

**目标**：1 小时内测完整条主线。拆解：

| 阶段 | 正常新手时长 | 压缩后（×1000 倍速） |
| --- | --- | --- |
| M1 山洞 | 5–10 分钟 | < 1 秒 |
| M2 村庄 | 30–45 分钟 | ~3 秒 |
| M3 小镇 | 2–3 小时 | ~10 秒 |
| M4 城市 | 3–5 小时 | ~20 秒 |
| M5 国家 | 4–6 小时 | ~30 秒 |
| 太空 | 5–8 小时 | ~40 秒 |
| **合计** | **~18 小时** | **~2 分钟**（含手动点引导） |

剩下 58 分钟留给"每阶段中间停一下，用真实速度跑 30 秒验证手感没坏"。

### 7.3 离线收益对通关时长的影响，怎么验

数值上：活跃 18h + 离线 ~43h 等效 = 玩家体感"挂 3 晚通关"。QA 要验证：

| # | Given | When | Then |
| --- | --- | --- | --- |
| F1 | 新存档，无任何加成 | 注入假时钟快进 8 小时（离线上限） | 收益 = 当前阶段产出 × 8h × 离线效率，不多不少 |
| F2 | 玩家在 M3 小镇阶段 | 离线 8h 后结算 | 离线**不产科技点、不涨人口、不触发随机事件**（对齐 04c §5 风险表） |
| F3 | 玩家连续 3 晚离线 | 每晚回来结算一次 | 每晚都是独立 8h cap，不会因为"累计离线 24h"多发钱 |
| F4 | 倍速 debug 模式 | 注入 8h 离线 | 倍速下离线结算公式**必须和正常速度完全一致**（只产资源，不因为倍速把 8h 当 8000h） |
| F5 | 玩家离线收益刚好把下一个建筑买出来 | 点"收下" | 下一个建筑按钮立即可点，不出现"钱够了但 UI 还置灰一帧" |

### 7.4 六阶段 checkpoint（快速回归节点）

每次改代码后，不需要走完整 18h，只需要跑到下表节点，验证"这个节点之后的链路没断"：

| 阶段 | checkpoint（在该阶段里要测的最小事） | 预计耗时（倍速下） |
| --- | --- | --- |
| M1 山洞 | 采浆果 → 生火 → 招第 1 个小人 | < 5 秒 |
| M2 村庄 | 5 个小人 + 茅草房 ×1 + 制陶科技解锁 | ~10 秒 |
| M3 小镇 | 木/石工具齐 + 人口 20 + 第一次阶段切换 | ~20 秒 |
| M4 城市 | 税收生效 + 科研点能花出去 + 建筑升级到 T2 | ~30 秒 |
| M5 国家 | 稀有矿开采 + 火箭燃料产线通 | ~40 秒 |
| 太空 | 戴森球建成 + 星尘入账 + 通关画面 | ~60 秒 |

**回归策略**：
- 日常开发：只跑上一行（当前阶段 checkpoint）。
- 每次发版：6 个 checkpoint 全跑一遍，< 3 分钟。
- 每次里程碑：跑一次完整 1 小时压缩通关 + 一次真实速度 M1~M3（手感受不能丢）。

## 8. 议题追加：可重玩性设计（QA 视角）

### 8.1 Prestige / 转生

**v1 既定方案（来自 04c）**：不做"清档重开"的硬转生；做"星尘"软 Prestige——通关一次给 ~5 星尘，全局 +50% 产出，**存档不清**。

**QA 要测的是**：

| # | 场景 | 断言 |
| --- | --- | --- |
| P1 | 第一次通关戴森球 | 星尘 +5，通关动画播完，存档里多 5 星尘 |
| P2 | 星尘已 5，开始新一轮（继续在原存档玩） | 全局产出 +50% 生效，**老的建筑/资源不重置** |
| P3 | 刷星尘：立刻再建一次戴森球（debug 给钱） | 星尘按规则递增，不出现"刷一次给 500" |
| P4 | 存档版本 v1 → v2（假设以后真加硬 Prestige） | 星尘字段迁移不丢，老存档能进新版本 |
| P5 | 星尘加成叠加 | 3 次通关 = +150%，数学上对，不是 +50%+50%+50%=+150%（不是 +375%） |

**风险点**：
- [ ] 星尘加成如果做成"乘法"而不是"加法"，三次通关会变 8 倍，数值爆炸——跟数值策划确认是 +50% 加法还是 ×1.5 乘法。
- [ ] 星尘存在 localStorage 里，和资源一样可被 F12 改。v1 认了，v2 服务端重算（见 §2.1）。

**如果未来要做硬 Prestige（v2+）**，必须现在就预留：
- 存档分两层：`meta`（星尘、成就、设置、每日挑战进度——转生保留）和 `run`（当前周目的建筑/资源/小人——转生清空）。
- 现在就把这两个字段分开存，别到时候重构。

### 8.2 世界种子（World Seed）

**v1 推荐方案**：v1 不做"同一 seed 必须完全一致"的硬核确定性（成本高，Phaser 寻路、动画时序都要锁）。做"软种子"——只影响：初始地形、随机事件序列、小人名字。**不影响数值平衡**。

**测试矩阵**：

| # | 场景 | 断言 |
| --- | --- | --- |
| S1 | 同 seed ×2 次新开 | 初始地形、前 10 个随机事件序列、小人名字**完全一致**（在"软种子"承诺范围内） |
| S2 | 不同 seed ×2 次新开 | 至少上面三项里有一项不同（证明 seed 真的生效了，不是写死） |
| S3 | 不填 seed（默认） | 每次新开都不同，但不报错 |
| S4 | 存档里不带 seed 字段（老档） | 自动生成新 seed，不崩 |
| S5 | 存档里的 seed 是非法字符串（`"abc"` / `""` / 超长） | 回退到随机 seed，不抛 |
| S6 | seed 影响寻路 / 资源位置 | **断言不影响**——同 seed 下资源总量在合理方差内，不因 seed 不同导致某局必卡 |

**风险点**：seed 只应影响"装饰 + 事件顺序"，**绝对不能影响数值曲线**。如果某 seed 天生石头多 3 倍，玩家会刷 seed 刷初始档，这是变相作弊。

### 8.3 随机事件（注入随机种子）

**必做**：游戏内所有 `Math.random()` 换成一个可注入的 RNG 实例（和 clock.ts 一个道理）。

| # | 场景 | 断言 |
| --- | --- | --- |
| R1 | 注入固定 seed | 连续触发 100 次"随机事件" | 两次跑完全部事件序列完全一致 |
| R2 | 注入固定 seed | 改一个无关变量（比如改了 UI 颜色） | 事件序列**不变**——证明事件真的走注入 RNG，没偷偷 Math.random |
| R3 | 事件概率 = 5% | 跑 10000 次 | 命中率 4.5%~5.5%（95% 置信区间内） |
| R4 | 离线期间 | 不触发任何随机事件（对齐 04c §5） |
| R5 | 事件触发瞬间玩家正在建造 | 事件弹窗不打断建造，关掉后建造继续 |

**风险点**：只要代码里还有一处裸 `Math.random()`，整个"可重现测试"就破了。code review 卡这条，ESLint 加 `no-restricted-syntax` 禁裸 Math.random（v2 再说，v1 先人工卡）。

### 8.4 多流派科技，怎么确保每条分支都能通关

**QA 立场**：v1 科技树如果是"全点"型（线性），不用测；如果是"二选一/三选一"分支，每条分支都要能走到戴森球。

**测试方法**：

| # | 场景 | 断言 |
| --- | --- | --- |
| T1 | 科技树有 N 条互斥分支 | 用 debug 控制台强制选分支 A，倍速通关 | 戴森球建成，无死路 |
| T2 | 同上 | 强制选分支 B、C…… | 每条分支独立通关一次，全过 |
| T3 | 只点某分支，其他一分不点 | 资源产出曲线不卡在"必须靠另一分支的资源" | 不出现"科技点被另一分支锁死" |
| T4 | 分支 A 通关一次，删档重来走分支 B | 成就"通关过 A 分支"仍在（成就跨周目保留） |

**风险点**：如果策划设计成"必须点 A 才能解 B 的前置"，那其实不是分支是线性，别让策划在文档里写"分支"结果代码是线性，测试会白写。**要求策划在 04c 里明确标出哪些节点真互斥。**

### 8.5 成就系统埋点

| # | 场景 | 断言 |
| --- | --- | --- |
| A1 | 首次达成成就条件 | 成就弹窗弹出一次，存档里 `unlockedAchievements` +1 |
| A2 | 刷新页面再打开 | 成就不重新弹（已解锁的不重复触发） |
| A3 | 两个成就条件同一帧满足（比如同时造了 10 个和 100 个建筑） | 两个弹窗排队依次出，不叠在一起 |
| A4 | 老存档 v0 没有 `achievements` 字段 | 迁移为空数组，不崩 |
| A5 | 成就条件是"累计 X 次" | 中途删档重开后，计数**按设计**：是跨周目累计还是本周目？文档必须写死 |
| A6 | F12 手动给存档塞个未解锁成就 ID | 读档时校验：条件没达成的成就不应被点亮（v1 可选做，做了加分） |

**埋点验证方法**：写一个 Vitest 用例，把所有成就 ID 跑一遍，确保每个成就都有对应触发路径——不能出现"这成就谁也拿不到"。

### 8.6 每日挑战 / 跨天种子（v1 可选，先把测试方案写着）

**v1 立场**：每日挑战是锦上添花，M5 之后再做。但现在把方案定下来，免得以后返工。

| # | 场景 | 断言 |
| --- | --- | --- |
| D1 | 同一天内打开游戏 3 次 | 每日挑战的 seed 相同（用"日期+密钥"做 seed 源，不依赖系统时间可被改） |
| D2 | 改系统时间到明天 | seed 变了，但**不能通过改时间反复刷今天的挑战**——服务端或"上次领取日期"字段防止 |
| D3 | seed 源 = `date(YYYY-MM-DD) + 固定盐` | 同一时区所有人同一天 seed 一致（跨时区问题见下） |
| D4 | 跨时区玩家 | 用 UTC 日期，不用本地日期——否则美国玩家凌晨 3 点挑战就变了 |

**风险点**：
- [ ] 跨天判定如果用 `new Date()`，改系统时间就能刷。和离线收益一个坑，必须复用 `clock.ts`，并且"每日重置"字段存到服务端（v2）。
- [ ] 每日挑战如果给奖励，奖励必须**不影响主线平衡**（比如只给皮肤/星尘碎片），否则玩家会为了每日挑战逼自己上线，违背挂机游戏"想玩就玩"的调性。

### 8.7 本章风险汇总（按优先级）

- [ ] **P0**：debug 倍速模式必须在 M2 前落地，否则 QA 自己测不完。
- [ ] **P0**：所有 `Math.random()` 走注入 RNG，否则随机事件不可重现。
- [ ] **P1**：存档分 `meta` / `run` 两层，为将来硬 Prestige 留路。
- [ ] **P1**：星尘加成是加还是乘，找数值策划拍板。
- [ ] **P2**：世界种子只影响装饰和事件，不影响数值——写进代码注释。
- [ ] **P2**：每日挑战 v1 不做，方案先存着。
