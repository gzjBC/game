# 技术选型详表

> 2026-09-17 定稿。本文档记录每个技术选型的理由、备选、踩坑预案。

## 一、为什么是 Web 栈，而不是游戏引擎

| 维度 | Web 栈（React + Phaser） | Godot 4 | Unity |
| --- | --- | --- | --- |
| 包体大小 | 300KB ~ 2MB gzip | Web 导出 ~10MB | WebGL 20MB+ |
| 首屏加载 | 1-3 秒 | 5-10 秒 | 10 秒+ |
| 手机浏览器兼容 | 原生好 | 一般（Safari WebGL 限制） | 差（iOS Safari 尤甚） |
| 挂机类需要的能力 | UI 面板 + 少量动画 | 杀鸡用牛刀 | 杀鸡用牛刀 |
| 与用户现有技术栈匹配 | JS/TS/Node 后端 ✓ | GDScript 新学 | C# 新学 |
| 作品集展示 | 一个网址，面试官点开就玩 | 要下载附件 | 要下载附件 |
| 后端联通 | 同语言（TS） | 单独写后端 | 单独写后端 |

**结论**：《High》90% 是 UI 面板（资源条 / 科技树 / 菜单）+ 10% 场景动画（小人走动）。这种结构用 React 写 UI 最快，Phaser 写场景最省，Web 栈是最自然的选择。

## 三、架构分层

```
┌─────────────────────────────────────┐
│ React 层（DOM）                      │
│  - 资源条 / 科技树 / 菜单 / 设置     │
│  - 订阅 Zustand store                │
└──────────────┬──────────────────────┘
               │ zustand/事件
┌──────────────┴──────────────────────┐
│ 游戏逻辑层（纯 TS，无 DOM）          │
│  - 资源计算 / 离线结算 / 存档读写    │
│  - 建筑 / 科技 / 阶段切换            │
└──────────────┬──────────────────────┘
               │ Phaser 场景事件
┌──────────────┴──────────────────────┐
│ Phaser 场景层（Canvas）              │
│  - tilemap / 小人精灵 / 动画 / 相机  │
│  - easystarjs 寻路                  │
└─────────────────────────────────────┘
```

关键原则：**游戏数值逻辑完全在纯 TS 层，不依赖 Phaser**。这样：
1. 单测可以纯跑 Node，不用启浏览器。
2. 以后想换渲染层（比如换 PixiJS）不影响数值。
3. 离线结算写在一个函数里，进游戏时调一次。

## 四、存档格式（v1）

```json
{
  "version": 1,
  "savedAt": 1726560000000,
  "resources": { "berries": 1234, "wood": 567 },
  "buildings": { "campfire": 1, "hut": 0 },
  "unlockedTech": ["fire"],
  "stage": 1,
  "workers": [{ "id": 1, "x": 5, "y": 3, "state": "idle" }]
}
```

- 用 localStorage 键名 `high-save-v1`。
- 每次玩家操作后 debounce 500ms 写一次。
- 页面 `visibilitychange` 隐藏时强制写一次。
- 加 `version` 字段，以后迁移存档时能判断。

## 五、离线收益算法（关键）

```ts
function applyOfflineProgress(save: SaveData): SaveData {
  const now = Date.now();
  const elapsedSec = Math.floor((now - save.savedAt) / 1000);
  // 离线收益上限：8 小时（v1 慷慨）
  const cappedSec = Math.min(elapsedSec, 8 * 3600);
  const multiplier = getOfflineMultiplier(save); // 瞭望塔等建筑加成
  // 每个建筑的产出 × cappedSec × multiplier
  for (const b of save.buildings) {
    save.resources[b.output] += b.ratePerSec * cappedSec * multiplier;
  }
  save.savedAt = now;
  return save;
}
```

**为什么不用 setTimeout 累计**：浏览器后台标签页会把 setInterval 节流到 1 次/分钟，手机浏览器直接杀掉进程。时间差是唯一可靠方案。

**防改系统时间**（v2 接后端后做）：服务端返回 `serverTime`，本地 `elapsedSec = (serverTime - save.serverSavedAt)`。

## 六、为什么选 Phaser 而不是裸 Canvas

- tilemap 加载（Tiled 编辑器导出的 JSON）开箱即用。
- 精灵动画（4 方向走路帧）有现成 API。
- 相机跟随、事件总线、场景切换都封装好了。
- 社区示例极多，遇到问题搜得到答案。
- 缺点：包体 ~1MB。对挂机游戏无所谓。

## 七、为什么用 Zustand 而不是 Redux

- 游戏状态是高频更新（每帧资源跳动），Redux 样板代码太多。
- Zustand 一个 `useStore()` hook 搞定，异步 action 原生支持。
- 和 React 18 并发模式兼容。

## 八、备选方案（如果 Phaser 学不动）

降级路线：
1. 直接用 React + `<canvas>` 手写小人移动（不超过 500 行代码）。
2. 用 p5.js 画场景，React 叠 UI。

升级路线（v2 之后）：
- 3D 化：换 Three.js / React Three Fiber。
- 联机：WebSocket + Colyseus。
